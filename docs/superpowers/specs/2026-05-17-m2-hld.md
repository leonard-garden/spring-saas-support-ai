## 1. Entity Relationship Diagram

```mermaid
erDiagram
    BUSINESS {
        uuid id PK
        string name
        string slug
        timestamptz created_at
    }
    KNOWLEDGE_BASE {
        uuid id PK
        uuid business_id FK
        timestamptz created_at
    }
    DOCUMENT {
        uuid id PK
        uuid knowledge_base_id FK
        uuid business_id
        string filename
        string content_type
        string minio_key
        string status
        bigint size_bytes
        int chunk_count
        text error_message
        timestamptz created_at
        timestamptz updated_at
    }
    DOCUMENT_CHUNK {
        uuid id PK
        uuid document_id FK
        uuid business_id
        text content
        int chunk_index
        int token_count
        varchar content_hash
        vector embedding
        tsvector fts_vector
        timestamptz created_at
    }

    BUSINESS ||--|| KNOWLEDGE_BASE : "has one"
    KNOWLEDGE_BASE ||--o{ DOCUMENT : "contains"
    DOCUMENT ||--o{ DOCUMENT_CHUNK : "split into"
```

**Key constraints:**
- `KNOWLEDGE_BASE.business_id` — UNIQUE (one KB per tenant)
- `DOCUMENT_CHUNK.embedding` — type `vector(1536)` (OpenAI text-embedding-3-small)
- `DOCUMENT_CHUNK.content_hash` — UNIQUE per `business_id` (SHA-256 dedup)
- `DOCUMENT_CHUNK.fts_vector` — GIN index for full-text search
- IVFFlat index on `embedding` for approximate nearest-neighbor search

## 3. Sequence Diagrams

### 3a. Document Upload Flow

```mermaid
sequenceDiagram
    actor User
    participant FE as Frontend
    participant DocCtrl as DocumentController
    participant DocSvc as DocumentService
    participant MinioSvc as MinioService
    participant DB as PostgreSQL

    User->>FE: Select file (PDF/TXT/MD)
    FE->>FE: Validate size ≤ 10MB, type allowed
    FE->>DocCtrl: POST /api/v1/kb/documents (multipart)
    DocCtrl->>DocSvc: upload(file, tenantId)
    DocSvc->>MinioSvc: store(file) → minioKey
    MinioSvc-->>DocSvc: minioKey
    DocSvc->>DB: INSERT document (status=PENDING)
    DocSvc-->>DocCtrl: DocumentResponse
    DocCtrl-->>FE: 202 Accepted {id, status: PENDING}
    FE-->>User: Document appears in list (PENDING badge)
```

### 3b. Async Processing Flow

```mermaid
sequenceDiagram
    participant DocSvc as DocumentService
    participant ProcSvc as ProcessingService @Async
    participant Router as IngestionRouter
    participant Ingester as PdfIngester / TextIngester
    participant Splitter as TokenTextSplitter
    participant Filter as ContentHashFilter
    participant OAI as OpenAI Embeddings
    participant PGV as PgVectorStore
    participant DB as PostgreSQL

    DocSvc--)ProcSvc: processAsync(documentId)
    Note over ProcSvc: Runs in separate thread
    ProcSvc->>DB: UPDATE status = PROCESSING
    ProcSvc->>ProcSvc: download file from MinIO
    ProcSvc->>Router: route(contentType)
    Router->>Ingester: read(inputStream)
    Ingester-->>ProcSvc: raw text
    ProcSvc->>Splitter: split(text, 500 tokens, overlap=50)
    Splitter-->>ProcSvc: List of chunks
    ProcSvc->>Filter: filter(chunks)
    Note over Filter: Remove chunks < 50 tokens<br/>Skip duplicate SHA-256 hashes
    Filter-->>ProcSvc: filtered chunks
    ProcSvc->>OAI: embed(chunks) batch call
    OAI-->>ProcSvc: float[] vectors
    ProcSvc->>PGV: add(documents with metadata)
    PGV->>DB: INSERT document_chunk rows
    ProcSvc->>DB: UPDATE status=READY, chunk_count=N
    Note over DB: FE polling detects READY
```

### 3c. RAG Search Flow

```mermaid
sequenceDiagram
    actor User
    participant FE as Frontend
    participant SearchCtrl as SearchController
    participant HybridSvc as HybridSearchService
    participant VecStore as VectorStorage
    participant FTSStore as FullTextStorage
    participant OAI as OpenAI Embeddings
    participant DB as PostgreSQL

    User->>FE: Enter query + click Search
    FE->>SearchCtrl: POST /api/v1/kb/search {query, topK:5}
    SearchCtrl->>HybridSvc: search(query, topK, businessId)
    par Vector Search
        HybridSvc->>OAI: embed(query)
        OAI-->>HybridSvc: query vector
        HybridSvc->>VecStore: similaritySearch(vector, k=5, businessId)
        VecStore->>DB: SELECT ... ORDER BY embedding <=> $vec LIMIT 5
        DB-->>VecStore: top-k chunks with scores
        VecStore-->>HybridSvc: List[SearchResult]
    and Full-Text Search
        HybridSvc->>FTSStore: search(query, businessId)
        FTSStore->>DB: SELECT ... WHERE tsvector @@ plainto_tsquery
        DB-->>FTSStore: matching chunks
        FTSStore-->>HybridSvc: List[SearchResult]
    end
    HybridSvc->>HybridSvc: merge + dedup by chunkId + sort by score
    HybridSvc-->>SearchCtrl: List[SearchResult] top-5
    SearchCtrl-->>FE: 200 {results: [...]}
    FE-->>User: Display results (content + score + source doc)
```

## 4. Technology Stack Decisions

| Layer | Technology | Rationale |
|---|---|---|
| File storage | MinIO (dev) / Cloudflare R2 (prod) | S3-compatible, open-source, free tier |
| Vector DB | pgvector extension on PostgreSQL | No extra infra, leverages existing PG |
| Embeddings | OpenAI text-embedding-3-small (1536 dim) | Fixed dim for both dev/prod; $5 cap on dev key |
| Text splitting | Spring AI TokenTextSplitter (500 tok, overlap 50) | Semantic coherence with overlap context |
| FTS | PostgreSQL tsvector + plainto_tsquery | Built-in, no Elasticsearch needed for MVP |
| Async processing | Spring `@Async` with dedicated thread pool | Simple, no Kafka/Redis needed for MVP |
| Ingestion abstraction | `DocumentIngester` interface | Extensible: VideoIngester, CsvIngester future |
| Storage abstraction | `StorageStrategy` interface | Swappable: VectorStorage, FullTextStorage |

## 6. Multi-Tenancy

All queries filtered by `business_id` via existing Hibernate tenant filter (`TenantContext`). Documents and chunks inherit `business_id` at INSERT time — no cross-tenant data leakage possible at the ORM layer.
